# Архитектура проекта OS_Lab13

## Обзор системы

Проект состоит из двух основных частей:
1. **lab10** - Базовая библиотека HT API (Hash Table API)
2. **lab4-ht-com-dll** - COM-обертка над HT API для межпроцессного взаимодействия

---

## 1. Базовая библиотека HT API (lab10)

### Структура компонентов

#### **OS10_HTAPI** - Статическая библиотека (.lib)
**Файлы:**
- `HT.h` / `HT.cpp` - Основной API для работы с хеш-таблицей
- `Element.h` / `Element.cpp` - Структура элемента данных (ключ/значение)

**Функциональность:**
- Создание и открытие HT-хранилища в памяти (File Mapping)
- Операции CRUD: insert, get, update, removeOne
- Автоматический snapshot (периодическое сохранение на диск)
- Синхронизация через Mutex для многопоточного доступа
- Хранение данных в формате ключ/значение

**Ключевые структуры:**
```cpp
HtHandle - блок управления HT (емкость, интервалы, файлы, mutex)
Element  - элемент данных (ключ, payload)
```

#### **OS10_01, OS10_02, OS10_03** - Тестовые приложения
**Назначение:** Демонстрация работы с HT API напрямую (статическая линковка)

**Взаимодействие:**
```
OS10_01.exe → OS10_HTAPI.lib → HT API функции
```

#### **TEST_CASES** - Набор тестов
**Назначение:** Автоматизированное тестирование функциональности HT API

---

## 2. COM-обертка (lab4-ht-com-dll)

### Архитектура COM-компонента

#### **OS13_HTCOM** - COM DLL-компонент
**Файлы:**
- `ComponentHT.h` / `ComponentHT.cpp` - Реализация COM-компонента
- `Interface.h` - Определение COM-интерфейсов (IHT, IElement)
- `ClassFactory.cpp` - Фабрика классов для создания компонентов
- `Registry.cpp` - Регистрация/отмена регистрации в реестре Windows
- `dllmain.cpp` - Точка входа DLL

**Взаимодействие:**
```
OS13_HTCOM.dll
    ↓ (линкуется)
OS10_HTAPI.lib
    ↓ (использует)
HT API функции
```

**COM-интерфейсы:**
- **IHT** - Интерфейс для работы с хеш-таблицей (create, open, insert, get, update, removeOne, snap, close)
- **IElement** - Интерфейс для создания элементов (createGetElement, createInsertElement, createUpdateElement)

**Регистрация:**
- При регистрации (`regsvr32 OS13_HTCOM.dll`) компонент добавляется в реестр Windows
- CLSID: `{693c66d1-3ce5-4512-a311-782618dbc7a6}`
- ProgID: `OS13.ComponentHT`

#### **OS13_HTCOM_LIB** - Обертка-библиотека для клиентов
**Файлы:**
- `OS13_HTCOM_LIB.h` / `OS13_HTCOM_LIB.cpp` - Упрощенный C++ API для работы с COM

**Назначение:** 
Упрощает использование COM-компонента, скрывая детали COM (CoCreateInstance, QueryInterface и т.д.)

**Функции:**
```cpp
OS13_HTCOM::Init() - Инициализация COM и создание компонента
OS13_HTCOM::HT::create/open/insert/get/update/... - Обертки над COM-интерфейсами
OS13_HTCOM::Dispose() - Освобождение ресурсов
```

**Взаимодействие:**
```
OS13_HTCOM_LIB.lib
    ↓ (использует)
COM API (CoCreateInstance, QueryInterface)
    ↓ (создает)
OS13_HTCOM.dll (ComponentHT)
    ↓ (вызывает)
OS10_HTAPI.lib (HT API)
```

## 3. Клиентские приложения

### **OS13_CREATE** - Создание HT-хранилища
**Назначение:** Создает новый файл HT-хранилища

**Взаимодействие:**
```
OS13_CREATE.exe
    ↓ (линкуется)
OS13_HTCOM_LIB.lib
    ↓ (использует COM)
OS13_HTCOM.dll
    ↓ (вызывает)
OS10_HTAPI.lib
    ↓ (создает)
HTspace.ht (файл на диске)
```

**Параметры:** `capacity secSnapshotInterval maxKeyLength maxPayloadLength filename`

### **OS13_START** - Запуск HT-хранилища
**Назначение:** Открывает существующее HT-хранилище и держит его в памяти

**Особенности:**
- Открывает HT через File Mapping (isMapFile=false)
- Ожидает нажатия клавиши или события "Stop"
- Выполняет финальный snapshot перед закрытием

**Взаимодействие:**
```
OS13_START.exe
    ↓
OS13_HTCOM_LIB.lib → OS13_HTCOM.dll → OS10_HTAPI.lib
    ↓
Открывает HTspace.ht через File Mapping
```

### **OS13_STOP** - Остановка HT-хранилища
**Назначение:** Устанавливает событие "Stop" для завершения работы OS13_START

**Взаимодействие:**
```
OS13_STOP.exe
    ↓
SetEvent("Stop")
    ↓
OS13_START.exe получает сигнал и завершается
```

### **OS_0402, OS_0403, OS_0404** - Параллельные клиенты
**Назначение:** Демонстрация параллельного доступа к HT-хранилищу

**Особенности:**
- Открывают HT через File Mapping (isMapFile=true)
- Могут работать параллельно с OS13_START
- Выполняют операции insert/get/update/removeOne

**Взаимодействие:**
```
OS_0402.exe / OS_0403.exe / OS_0404.exe
    ↓ (параллельно)
OS13_HTCOM_LIB.lib → OS13_HTCOM.dll → OS10_HTAPI.lib
    ↓
Открывают HTspace.ht через File Mapping (общая память)
    ↓
Синхронизация через Mutex в HtHandle
```

## 4. Поток данных и взаимодействие

### Сценарий работы:

1. **Регистрация COM-компонента:**
   ```
   regsvr32 OS13_HTCOM.dll
   → Registry.cpp регистрирует компонент в Windows Registry
   ```

2. **Создание HT-хранилища:**
   ```
   OS13_CREATE.exe 2000 3 4 4 "HTspace.ht"
   → OS13_HTCOM::HT::create()
   → ComponentHT::create()
   → ht::create() (из OS10_HTAPI)
   → Создает файл и File Mapping
   ```

3. **Запуск сервера:**
   ```
   OS13_START.exe HTspace.ht
   → Открывает HT через File Mapping
   → Держит хранилище в памяти
   → Ожидает события "Stop"
   ```

4. **Параллельный доступ:**
   ```
   OS_0402.exe (параллельно)
   → Открывает тот же File Mapping
   → Выполняет insert/get/update
   → Синхронизация через Mutex
   ```

5. **Остановка:**
   ```
   OS13_STOP.exe
   → Устанавливает событие "Stop"
   → OS13_START завершается
   → Выполняется финальный snapshot
   ```

## 5. Технологии и механизмы

### File Mapping (Memory-Mapped Files)
- **Назначение:** Общая память между процессами
- **Использование:** HT-хранилище находится в общей памяти
- **Файлы:** `HTspace.ht` - физический файл на диске

### COM (Component Object Model)
- **Назначение:** Межпроцессное взаимодействие
- **Реализация:** In-Process Server (DLL)
- **Интерфейсы:** IHT, IElement

### Синхронизация
- **Mutex:** Защита критических секций в HT API
- **WaitableTimer:** Автоматический snapshot по таймеру
- **Events:** Сигнализация между процессами (Stop event)

### Snapshot механизм
- **Автоматический:** По таймеру (secSnapshotInterval)
- **Ручной:** Вызов snap()
- **При закрытии:** Автоматический snapshot в close()

## 7. Файлы данных

- **HTspace.ht** - Файл хеш-таблицы на диске
- **Структура:** HtHandle + массив элементов
- **Формат:** Memory-mapped file для быстрого доступа

---

## 8. Порядок сборки

1. Собрать `OS10_HTAPI` → получаем `OS10_HTAPI.lib`
2. Собрать `OS13_HTCOM` → получаем `OS13_HTCOM.dll` (линкуется с OS10_HTAPI.lib)
3. Собрать `OS13_HTCOM_LIB` → получаем `OS13_HTCOM_LIB.lib`
4. Собрать клиентские приложения → линкуются с OS13_HTCOM_LIB.lib

---

## 9. Ключевые моменты взаимодействия

1. **Прямой доступ (lab10):** Приложения напрямую используют OS10_HTAPI.lib
2. **COM-доступ (lab4-ht-com-dll):** Приложения используют COM через OS13_HTCOM_LIB.lib
3. **Общая память:** Все процессы работают с одним File Mapping
4. **Синхронизация:** Mutex защищает операции чтения/записи
5. **Персистентность:** Snapshot сохраняет данные на диск
